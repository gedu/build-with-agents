# skills/

Tool-neutral skills. This directory lives at the **repo root** on purpose: `.claude/skills`,
`.gemini/skills` and `.codex/skills` are symlinks to it, generated by `./setup.sh`.

Skills are not enumerated here; the directory carries the truth and `MAP.md` carries the count.

## Layout

| Path | Required | Contents |
|------|----------|----------|
| `<skill-name>/SKILL.md` | yes | The skill itself: trigger, procedure, output shape |
| `<skill-name>/references/` | no | Long material the skill loads on demand |
| `<skill-name>/assets/` | no | Templates, snippets, fixtures the skill copies |

One directory per skill. `kebab-case` names. No loose `.md` files at this level except this README.

## Belongs here / does NOT

- Yes: procedures an executor should follow, written for an LLM to act on, working in any
  executor and referencing repo-relative paths only.
- No: tool-specific configuration, hooks, or settings; theory or rationale (`theory/`,
  `decisions/`); absolute paths or a vendor's proprietary frontmatter fields.

## Frontmatter contract

`SKILL.md` uses the repo schema from `AGENTS.md` with `type: skill`:

```yaml
---
id: skills/<skill-name>
type: skill
targets: [react, react-native, any]
status: draft
verified: 2026-08-05
sources: []
---
```

A skill reaches `status: validated` only after being run end to end at least once, with
that run referenced in `sources`.
